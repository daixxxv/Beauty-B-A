# 1. サービス概要

美容系の施術を受ける方、また施術者がお顔の変化を時系列に沿って比較しやすくするサービス。

Before/Afterを横並びで比較し、自分やお客様の変化を一目で分かりやすく実感してもらうことを目的としています。

# 2. このアイデアはどこから生まれたか

## 2-1. きっかけとなった体験・感情

鍼灸師をしており、お顔やお身体のBefore/Afterを感じてもらうには、写真で見た方が分かりやすいため。

また、継続していく中で、自分自身でも変化を実感してもらいたいため。

## 2-2. なぜそれが「気になった」のか

鍼灸師としてお客様と関わっていく中で、お客様のお悩みを少しでも改善させてあげようと施術を行っていました。

ただ、施術をするだけでは「スッキリした！」などの感想は出てきますが、実際にどれくらい変化したのかが分からないため、可視化できるようにしたいと思ったため。

# 3. 課題の整理

## 3-1. 表に見えている困りごと

施術前後の写真を毎回撮影すること、それを継続することが難しい。

また、振り返る機会がなかったりするため、自分で変化や効果を実感しにくい。

## 3-2. 本当に解決したい課題は何か

鍼灸施術に限らず、美容系や姿勢矯正などは、良くなっていくのに時間がかかってしまう場合があります。

その間に振り返る機会がないと、効果を実感してもらいづらくなります。その結果、継続できず、これまでアプローチしてきた中で細かく変化している部分を実感できない場合が多いです。

そのため、少しでも効果や変化を実感してもらえるようなサービスを提供したいと考えています。

# 4. 想定しているユーザーについて

## 4-1. 想定しているユーザー

美容系の施術や姿勢矯正などを月〜年単位で受けている方。

施術による変化を感じづらい、または感じていただけない方。

## 4-2. 自分とユーザーの距離

身近な方、またはお客様。

鍼灸師としてお客様を相手に使用すること、また、自分自身の変化を感じてもらうことを想定しているため。

## 4-3. 実際に使われる可能性について

美容系の施術を受けている方は、何かしらの美容系アプリを入れている方も多い。

また、施術者側も仕事で使用していたり、普段からアプリを使用していたりする方もいる。

そこで、変化を時系列順に簡単に見られ、状態が良くなった自分を振り返って見ることで、自分のことをより好きになっていけるアプリであれば、利用したいと思っていただけるのではないかと考えています。

## 4-4. ユーザーがサービスを導入して利用するまでのイメージ

美容系の施術を受けているお客様、または施術者が、施術の効果や変化を可視化して記録したいと思った際に利用できるアプリ。

新規登録後、撮影した写真を比較することで変化を見ることができます。

その後も施術後の写真やメモを残していくことで、最初の頃との変化も分かりやすく見られるようになります。

## 5-2. それでも自分が作りたい理由

上記の2つは、実際に現場で私や他のスタッフが使用しているアプリです。

写真を比較することができ、見やすい一方で、保存してアルバムとして後から見やすくする機能はないため、写真を保管して後から振り返ることができるアプリを作りたいと思いました。

## 5-3. 差別化を「体験価値」で表現する

自分が調べた中では、現在あるアプリは、その時のBefore/Afterを比較することが目的となっています。

本サービスは、その時の比較もでき、また過去の写真とも比べることで、「変化を体感すること」を目的としています。

# 6. このサービスで提供したい価値

## 6-1. ユーザーの変化

**行動の変化：**
定期的に振り返って、変化を見たくなる。

**気持ちの変化：**
過去の自分と、今の良くなってきている自分を比べることで、モチベーションが上がる。

**考え方の変化：**
変化を見ることが楽しくなり、写真を撮って記録していこうと思うようになる。

## 6-2. 価値を一文で表す

美容系の施術を受けている人、または施術者が、効果や変化を可視化できるようになるサービス。

# 8. このアプリの懸念点とその対策

**懸念点**

・何が問題になりそうか：
ユーザーが写真を撮って記録していくことができない可能性。

・なぜそう思うか：
個人差はありますが、美容系の施術は最初の頃は変化が分かりづらかったり、変化が出るまでに時間がかかったりする場合があるため、本当に効果があるのか分からなくなる場合があります。

・そのために考えている対策：
Before/Afterを比較する際に、グリッド線などの機能を使い、細かいところまで比較しやすくする。

また、定期的に振り返る機能を設ける。

# 10. 技術スタック

## 10-1. 使用予定の技術

・フレームワーク：Ruby on Rails、Tailwind CSS
・DB：PostgreSQL
・デプロイ先：Render
・開発環境：Docker

## 10-2. 技術選定の比較検討

・Rails：採用
カリキュラムでの学習経験があり、開発効率が高いため。

・Tailwind：採用
デザインが調整しやすいため。

・PostgreSQL：採用
Railsとの相性が良いため。

## 10-3. キャッチアップ不足の懸念

現時点では、キャッチアップ不足により実装難易度が高い。

そのため、MVPではコア機能の実装を行い、Before/After比較と記録に必要な最小限の機能を実装する。

将来的には、メモ機能やアルバム機能、タグ付け機能や検索機能の導入を検討している。
